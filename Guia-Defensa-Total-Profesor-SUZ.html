Capítulo 1

Explicación General del Proyecto

1.1 ¿Qué hace la aplicación y cuál es su objetivo?

SUZ es un CRM Comercial y de Fidelización de Ventas Recurrentes diseñado a medida para una empresa distribuidora mayorista de materias primas e insumos (específicamente harina y azúcar).

El objetivo principal no es solo guardar clientes como una libreta de direcciones estática, sino predecir el momento exacto en el que cada cliente se quedará sin mercadería para que los preventistas y vendedores se anticipen y gestionen la recompra vía WhatsApp en un clic, además de controlar en vivo los saldos deudores de las cuentas corrientes.

1.2 ¿Qué problema real resuelve?

  • El problema de las ventas perdidas por olvido: Las panaderías y comercios compran harina cada 7, 15 o 30 días. Si el vendedor no llama a tiempo, el cliente le compra a la competencia. El sistema resuelve esto calculando automáticamente la Próxima Compra Estimada y mostrando un Semáforo Comercial (Verde: con stock, Amarillo: compra hoy, Rojo: vencido).
  • El problema del cálculo mental de deudas: En el rubro mayorista se venden miles de kilos con pagos parciales (seña o entrega de dinero). Los vendedores solían cometer errores calculando a mano. El sistema calcula en vivo: Total = Kilos × Precio y Deuda = Total - Monto Pagado.
  • El problema de la confidencialidad geográfica: Vendedores de una provincia no deben ver ni editar clientes de otra provincia. El sistema implementó un control de acceso por roles (Login) que aísla las carteras de Chaco (Gran Resistencia), Corrientes e Interior de Chaco.

1.3 ¿Cómo funciona desde que el usuario la abre? (Flujo de Usuario)

  1. Inicio de Sesión: El usuario ingresa en /login. Si es vendedor de Chaco, Corrientes o Interior, ingresa su usuario y contraseña (o usa la botonera de 1 clic para la demo).
  2. Redirección de Seguridad: Si el usuario es vendedor de Chaco, el guardián de rutas (ProtectedRoute) lo dirige exclusivamente a /Chaco. Si intenta tipear /corrientes en la URL, el sistema detecta que no tiene permiso y lo devuelve a su zona. Si ingresa el admin, tiene acceso universal a todas las zonas.
  3. Tablero Provincial Segmentado: La pantalla divide automáticamente los clientes en dos secciones visuales: 🔴 Con Deuda Pendiente y 🟢 Clientes al Día.
  4. Acción Comercial: En cada tarjeta el vendedor ve el semáforo de reposición. Si está en amarillo o rojo, presiona el botón 💬 WhatsApp: se abre la aplicación con un mensaje prefabricado que incluye el nombre del comercio y del contacto para coordinar la reposición.
  5. Gestión de Cobranzas: Si el cliente abona su saldo adeudado, el vendedor hace clic en 💵 Saldar. El sistema pone la deuda en $0 en tiempo real, actualiza la base de datos MySQL y dispara una notificación flotante Toast de confirmación.

2.1 Análisis de Impacto: ¿Qué pasaría si falta un archivo clave?

Archivo Función Crucial ¿Qué pasaría si faltara o estuviera dañado?
Server/src/db.js Crea la conexión Sequelize a MySQL y vincula los modelos. El backend no puede arrancar. Arroja error de conexión inmediatamente y ninguna ruta responde porque no hay instancia de base de datos.
Server/src/models/Clientes.js Define la estructura exacta de las columnas y tipos de datos en MySQL. Sequelize no sabría cómo mapear los datos. Las consultas fallarían y la tabla Clientes no existiría en la base de datos.
my-app/src/utils/config.js Centraliza la constante API_URL leída desde variables de entorno. Todas las vistas y acciones de Redux perderían la dirección del servidor y no sabrían a qué puerto o dominio hacer las peticiones HTTP.
my-app/src/components/ProtectedRoute.jsx Intercepta el acceso a cada pantalla y redirige si no hay permisos. Cualquier persona que escriba la URL podría acceder a la información de cualquier provincia sin necesidad de iniciar sesión.
my-app/src/redux/store.js Crea el contenedor del estado global de la aplicación. El componente <Provider> en index.js fallaría y React arrojaría un error fatal en blanco al intentar montar la app.

Capítulo 3

Explicación del Código Paso a Paso: Backend (Node.js & Express)

El backend sigue una arquitectura modular en tres capas: Ruta → Controlador → Modelo (ORM).

3.1 Conexión a Base de Datos con Sequelize: Server/src/db.js

💡 Concepto Previo: ¿Qué es un ORM y por qué usamos Sequelize?
Un ORM (Object-Relational Mapping) es un traductor. En lugar de escribir código SQL manual como SELECT * FROM Clientes WHERE id = 1, usamos métodos de JavaScript como Clientes.findByPk(1). Sequelize se encarga de hablar con MySQL por nosotros.
require('dotenv').config(); // 1. Carga variables desde el archivo .env const { Sequelize } = require('sequelize'); const Clientesmodels = require("./models/Clientes"); // 2. Leemos credenciales con valores por defecto seguros para desarrollo local const DB_NAME = process.env.DB_NAME || 'gestionclientes'; const DB_USER = process.env.DB_USER || 'root'; const DB_PASSWORD = process.env.DB_PASSWORD !== undefined ? process.env.DB_PASSWORD : 'gala12345'; const DB_HOST = process.env.DB_HOST || 'localhost'; const DB_PORT = process.env.DB_PORT || 3306; // 3. Instanciamos la conexión a MySQL const sequelize = new Sequelize(DB_NAME, DB_USER, DB_PASSWORD, { host: DB_HOST, port: DB_PORT, dialect: 'mysql', logging: false, // Apaga los logs extensos de SQL en la consola }); Clientesmodels(sequelize); // 4. Inicializa el modelo pasándole la conexión

Explicación línea por línea:

  • require('dotenv').config(): Lee el archivo privado .env y carga sus valores en el objeto global process.env de Node.js.
  • process.env.DB_PASSWORD !== undefined ? ... : 'gala12345': Es un operador ternario de respaldo. Si la variable existe en .env la utiliza; si por alguna razón el archivo .env falta, usa la clave por defecto para que la aplicación no se caiga.
  • dialect: 'mysql': Le indica a Sequelize que el motor de base de datos subyacente es MySQL (y no PostgreSQL o SQLite).

3.2 Modelo de Datos: Server/src/models/Clientes.js

💡 Concepto Previo: ¿Por qué UUID en lugar de ID numérico 1, 2, 3?
Si usamos IDs numéricos secuenciales (1, 2, 3...), un atacante o competidor puede adivinar fácilmente cuántos clientes tiene la empresa o intentar verlos cambiando el número en la URL (/clientes/4). Un UUID (Universal Unique Identifier) genera una cadena alfanumérica única en el mundo de 36 caracteres (ej: b372f107-074d-4abf-816e-a7534ccf0f33), garantizando seguridad e imposibilidad de adivinarlo.
sequelize.define("Clientes", { id: { type: DataTypes.STRING(36), defaultValue: () => uuidv4(), // Genera automáticamente el UUID v4 primaryKey: true, allowNull: false, }, name: { type: DataTypes.STRING, unique: true }, contacto: { type: DataTypes.STRING, allowNull: true }, provincia: { type: DataTypes.STRING, allowNull: false }, frecuencia: { type: DataTypes.INTEGER, defaultValue: 7 }, // Días de reposición cantidadKg: { type: DataTypes.DECIMAL(10, 2), defaultValue: 0 }, precioKg: { type: DataTypes.DECIMAL(10, 2), defaultValue: 0 }, monto: { type: DataTypes.DECIMAL(12, 2), defaultValue: 0 }, // Pago entregado deuda: { type: DataTypes.DECIMAL(12, 2), defaultValue: 0 }, // Saldo pendiente });

Por qué usamos DECIMAL(12, 2) en lugar de DECIMAL(8, 2):

  • Un DECIMAL(8, 2) solo permite 6 dígitos enteros y 2 decimales, lo que equivale a un máximo de $999.999,99 (menos de un millón de pesos). En la venta mayorista de harina por toneladas, un pedido real de un cliente ("La Reina") superaba $1.320.000, lo que hacía crashear la base de datos con el error "Out of range value".
  • Con DECIMAL(12, 2) el sistema soporta valores de hasta $9.999.999.999,99 (casi diez mil millones de pesos), ideal para el comercio mayorista argentino con alta inflación.

3.3 Arranque y Migración Segura: Server/src/index.js

const app = require("./app"); const { sequelize } = require("./db"); const PORT = process.env.PORT || 3001; (async () => { try { await sequelize.authenticate(); // 1. Prueba que el usuario y clave de MySQL sean válidos await sequelize.sync({ alter: true }); // 2. MIGRADOR SEGURO: actualiza columnas sin borrar datos app.listen(PORT, () => { console.log(`🚀 Servidor corriendo en http://localhost:${PORT}`); }); } catch (error) { console.error("❌ Error:", error.message); process.exit(1); } })();
⚠️ Pregunta Clave de Examen: ¿Por qué nunca usamos force: true en producción?
Si pusiéramos sync({ force: true }), Sequelize ejecutaría un comando DROP TABLE destructivo en cada reinicio del servidor, borrando absolutamente todos los clientes y las ventas guardadas. En su lugar, usamos { alter: true }, que compara los modelos en JavaScript contra la estructura existente de MySQL y ejecuta sentencias ALTER TABLE ADD COLUMN, preservando el 100% de los datos históricos.

4.1 Control de Acceso y Guardián de Rutas: auth.js y ProtectedRoute.jsx

💡 Concepto Previo: ¿Cómo sabe React si el usuario está logueado?
El protocolo HTTP es "stateless" (no tiene memoria entre páginas). Para recordar la sesión en el navegador sin recargar, guardamos un objeto de usuario en el localStorage del navegador. Al navegar, nuestro componente de seguridad lee el localStorage y decide si renderiza la pantalla o redirige.
// my-app/src/components/ProtectedRoute.jsx const ProtectedRoute = ({ component: Component, render, rolPermitido, ...restoDeProps }) => { return ( <Route {...restoDeProps} render={(props) => { const usuario = obtenerUsuarioActual(); // Lee desde localStorage // 1. Si no hay sesión activa, va directo al login if (!usuario) return <Redirect to="/login" />; // 2. El Administrador tiene acceso total a cualquier ruta if (usuario.rol === "admin") return Component ? <Component {...props} /> : render(props); // 3. Si coincide el rol (ej: rol 'chaco' en pantalla /Chaco) if (usuario.rol === rolPermitido) return Component ? <Component {...props} /> : render(props); // 4. SEGURIDAD: Si un vendedor intenta entrar a una provincia ajena, lo rebotamos a la suya const mapaRutas = { chaco: "/Chaco", corrientes: "/corrientes", interior: "/Interior" }; return <Redirect to={mapaRutas[usuario.rol] || "/login"} />; }} /> ); };

4.3 Conexión Asíncrona con el Backend: my-app/src/redux/actions.js

💡 Concepto Previo: ¿Qué es una acción asíncrona en Redux Thunk?
Por defecto, las acciones de Redux son instantáneas y síncronas (retornan un simple objeto { type, payload }). Como comunicarnos con el servidor MySQL toma tiempo por la red, Redux Thunk nos permite retornar una función asíncrona que hace un await axios.get(...) y recién cuando llegan los datos del servidor, despacha el resultado al reducer.

Despacha al reducer para que la pantalla se actualice al instante dispatch({ type: "POST_CLIENTE", payload: res.data }); return res; } catch (error) { console.error("❌ Error al crear cliente:", error); } }; };

Capítulo 6

Las 5 Partes Más Difíciles del Proyecto (Explicadas para Principiantes)

1. ¿Por qué usamos Redux y Redux-Thunk en lugar de un simple useState?

Explicación Simple:
Imagina que useState es una nota adhesiva que solo puede leer una persona en su escritorio (un componente). Si el formulario crea un cliente, la vista de Chaco no se entera porque está en otra habitación. Redux es una pizarra gigante en el pasillo (el Store): cualquier componente puede escribir en la pizarra y todos los demás componentes se actualizan automáticamente al instante.

En nuestro código: Cuando Form.jsx registra un cliente, despacha POST_CLIENTE. El Store se actualiza y cuando el usuario entra a Chaco.jsx, el nuevo cliente ya aparece listado sin tener que recargar el navegador ni pasar datos de padre a hijo por 10 niveles (evitando el llamado Prop Drilling).

2. La Migración Segura en MySQL: sync({ alter: true }) vs sync({ force: true })

Explicación Simple:
Imagina que construiste una casa de dos habitaciones (tu tabla en la base de datos) y ya viven personas adentro (los datos de los clientes). Si quieres agregar un garaje:
  • force: true: Demuele la casa con una bola de demolición (DROP TABLE) y construye una casa nueva vacía. Toda la gente muere (se pierden los datos).
  • alter: true: Llama a los albañiles para que construyan únicamente el garaje (ALTER TABLE ADD COLUMN) sin molestar a los que viven adentro.

3. El Guardián de Rutas (Higher Order Component en React Router v5)

Explicación Simple:
En React Router estándar, una ruta es pública: quien tipea /Chaco en el navegador entra sin filtro. ProtectedRoute actúa como el guardia de seguridad de un edificio: antes de dejarte pasar a la oficina, te pide identificación (lee el localStorage). Si no tienes gafete, te manda a la recepción (/login). Y si tienes gafete de vendedor de Chaco pero intentas entrar a la oficina de Corrientes, te acompaña de vuelta a tu oficina propia.

4. Inmutabilidad en Redux y el Operador Spread (...state)

Explicación Simple:
En JavaScript, React detecta que debe redibujar la pantalla cuando cambia la referencia de memoria de un objeto. Si haces state.clientes.push(nuevo), modificas el array original, React no nota el cambio y la pantalla se queda congelada. Al hacer [...state.clientes, action.payload], creas una fotocopia nueva con el nuevo elemento agregado. React ve una nueva dirección de memoria y redibuja la pantalla inmediatamente.

5. Normalización y Sincronización de Nombres Full Stack

Explicación Simple:
Uno de los errores más comunes en proyectos junior es que la pantalla llama a un campo frecuencia, el controlador intenta leer frecuenciaCompra y el modelo de MySQL lo espera como FrecuenciaDecompra. Como JavaScript distingue mayúsculas y minúsculas (es case-sensitive), MySQL recibía undefined y guardaba ceros o nulos. Lo solucionamos estandarizando exactamente las mismas variables en las 3 capas: contacto, frecuencia, producto, marca, cantidadKg, precioKg, monto y deuda.

Banco de Preguntas de Examen y Respuestas Modelo

A continuación tienes las preguntas reales que cualquier profesor o jurado técnico te hará, con la respuesta exacta que debes dar:

❓ Pregunta 1: "¿Por qué utilizaste Redux si React ya tiene useState y Context API?"

Respuesta modelo: "Utilicé Redux porque el estado de los clientes es compartido por múltiples pantallas que no tienen relación directa de padre e hijo: el formulario de alta, las tres vistas provinciales y las búsquedas por nombre. Con Redux logramos una arquitectura unidireccional y un único punto de verdad (Single Source of Truth). Además, al combinarlo con Redux Thunk, podemos encapsular todas las llamadas asíncronas hacia la API de Express de forma ordenada y predecible fuera de los componentes de la interfaz."

❓ Pregunta 2: "¿Cómo manejaste la persistencia de sesión en el frontend sin usar JWT en el backend?"

Respuesta modelo: "Para esta etapa del proyecto implementamos una solución liviana basada en roles utilizando localStorage del navegador mediante el módulo auth.js. Cuando el usuario se autentica en la vista de Login, guardamos su objeto de perfil (rol y zona). Nuestro componente ProtectedRoute intercepta cada cambio de ruta en React Router v5: si el usuario no existe en localStorage, redirige a /login; y si el rol no coincide con la provincia a la que intenta ingresar, lo redirige automáticamente a su área asignada. Para producción, el siguiente paso evolutivo sería migrar esta validación a tokens firmados JWT con cookies HttpOnly."

❓ Pregunta 3: "¿Cómo resolviste el desbordamiento numérico en los campos de deuda en MySQL?"

Respuesta modelo: "Originalmente los campos de monto y deuda estaban tipados como DECIMAL(8, 2), lo que imponía un límite máximo de $999.999,99. Al cargar pedidos reales de clientes mayoristas con deudas superiores a 1,3 millones de pesos, MySQL lanzaba el error 'Out of range value'. Lo solucioné modificando el modelo en Sequelize a DECIMAL(12, 2), lo que nos permite almacenar importes comerciales de hasta diez mil millones de pesos con precisión de centavos sin redondeos erróneos de coma flotante."

❓ Pregunta 4: "¿Qué es CORS y por qué tuviste que configurarlo en app.js?"

Respuesta modelo: "CORS significa Cross-Origin Resource Sharing (Intercambio de Recursos de Origen Cruzado). Es un mecanismo de seguridad de los navegadores que bloquea las peticiones cuando el frontend (que corre en el puerto 3000) intenta pedirle datos a un servidor en otro puerto o dominio (el backend en el puerto 3001). En app.js configuramos el middleware cors() leyendo la variable de entorno CLIENT_URL para indicarle al servidor qué dominios tienen autorización para consumir nuestros endpoints."

❓ Pregunta 5: "¿Cómo funciona el botón Saldar en la tarjeta?"

Respuesta modelo: "En Card.js, el botón Saldar toma el monto total del pedido (kilos × precio) y ejecuta un dispatch de updateClientes enviando el cliente con monto: montoTotal y deuda: 0. Esto viaja por Axios por método PUT a /clientes/:id. El controlador de Express actualiza la fila en MySQL con cliente.save() y el frontend actualiza el estado local mostrando al instante la deuda en verde ($0) y disparando una notificación Toast de confirmación sin recargar la pantalla."

Glosario Técnico de Programación (Términos Reales del Proyecto)

Término Definición Sencilla Ejemplo en el Proyecto SUZ
API REST Conjunto de reglas y endpoints HTTP (GET, POST, PUT, DELETE) para comunicar el frontend con el backend. POST http://localhost:3001/clientes para dar de alta un comercio en el servidor.
ORM (Sequelize) Librería que mapea tablas relacionales a clases y objetos en JavaScript. Clientes.findByPk(id) en lugar de SELECT * FROM Clientes WHERE id = ?.
Single Source of Truth Principio arquitectónico donde todos los componentes leen los datos de un único almacén central. El Store de Redux donde reside el array clientes para toda la aplicación.
Middleware Función intermedia que intercepta una petición HTTP antes de que llegue al controlador final. express.json() que parsea el cuerpo de la solicitud, o cors() que valida el origen.
Hook de React Función especial (que empieza con use) que permite a componentes funcionales usar estado y efectos. useState para formularios locales, useEffect para traer datos, useToast para alertas.
HOC / ProtectedRoute Componente envoltorio que condiciona el renderizado de una vista a si se cumplen ciertas reglas lógicas. ProtectedRoute verifica si hay sesión en localStorage antes de mostrar la provincia.
Spread Operator (...) Sintaxis de 3 puntos que descompone un objeto o array para clonarlo sin mutar el original. { ...state, clientes: action.payload } en reducer.js.
Variables de Entorno Valores de configuración externos al código cargados dinámicamente según el entorno (desarrollo o producción). process.env.DB_PASSWORD en el servidor o REACT_APP_API_URL en React.
Glassmorphism Técnica de diseño UI que imita un vidrio translúcido con desenfoque de fondo y bordes brillantes. Las notificaciones flotantes en Toast.css con backdrop-filter: blur(16px).
